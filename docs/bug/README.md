# docs/bug/ — 事故复盘

记录**已经发生、值得留档**的 bug——不是日常的 issue 跟踪（那属于 GitHub
Issues），而是"排查过程本身有参考价值"或"根因不明显、以后可能再犯"的问题。文件名
`YYYY-MM-DD-<slug>.md`。

## 什么值得写在这里

- 排查耗时较长、过程中走过弯路的问题（记录弯路本身就是价值，帮后来者少走）。
- 根因涉及本模板的架构假设被打破的情况（如"以为进程内缓存跨请求存活，实际边缘运行时并不保证"这类，见
  `ARCHITECTURE.md §12.1` 的说明）。
- 任何最终改动了 `ARCHITECTURE.md`/`docs/*.md` 规范的
  bug（复盘里要链接对应改动的 PR 与更新后的文档章节）。

## 模板

```markdown
# YYYY-MM-DD: <一句话描述问题>

- 影响范围：<模块/平台/用户可见程度>
- 发现方式：<用户反馈 / 监控告警 / 测试发现>

## 现象

<具体表现，附日志片段——按 `Logging.md` 的格式截取>

## 排查过程

<按时间顺序，包括排除掉的错误方向，不要只写"最终发现是...">

## 根因

<真正的原因>

## 修复

<改了什么，链接 PR/commit>

## 如何避免复发

<新增的测试用例 / 静态检查规则 / 文档更新，链接对应改动>
```
