# i18n.md — 国际化规范

对应
[`ARCHITECTURE.md §11`](../ARCHITECTURE.md#11-国际化i18n)。支持简体中文（默认）、繁体中文、英文。

## 1. 目录与加载

```
shared/i18n/{zh-CN,zh-TW,en}.json     # Shell 级通用文案
modules/<id>/i18n/{zh-CN,zh-TW,en}.json  # 模块私有文案，随模块懒加载
```

字典一律经 `fetch` + `JSON.parse` 加载（`shared/lib/fetch-json.js`），
**不用动态 `import()`**：import attributes（`with/assert`）在旧浏览器 （Firefox
ESR 等）运行时被直接拒绝，会导致整屏裸 key。URL 以
`new URL(relative, import.meta.url)` 解析，与部署路径无关。

- 启动：`app/i18n/bootstrap.js` 的 `loadLocaleDictionaries(locale)` 加载
  `shared/i18n/` 与**当前语言的全部模块文案**（只加载当前语言，不拉所有语言，
  按语言幂等、失败可重试）——侧栏菜单标签（`module.json` 的 `labelKey`）
  首屏就需要翻译，不能等模块被访问。
- 运行时切换语言：lang-switch 广播 `locale:changed` → `app-shell.js` 的
  `handleLocaleChanged` 先 `await loadLocaleDictionaries(目标语言)` 再
  `renderApp()` + `navigate()` 重挂当前路由（字典未就绪就渲染会经回退链
  落回旧语言/裸 key；链路由 `tests/unit/lib/i18n-switch.test.js` 回归保护）。
- 模块兜底：模块 `index.js` 调 `registerModuleI18n(import.meta.url)`
  （`shared/lib/module-i18n.js`）幂等注册本模块字典，失败静默。

key 一致性由 `scripts/check-i18n-keys.js` 守护（经 `run-checks.js` 接入
`just lint`）：三语文件必须齐全、key 集合与 zh-CN 完全一致、不允许空翻译。

## 2. Key 命名规则

`<module>.<area>.<name>`，例如：

- `notes.menu.title` / `notes.menu.all`（侧栏菜单，见 `module.json` 的
  `labelKey`）
- `notes.action.create` / `notes.action.delete.confirm`
- `notes.empty.title` / `notes.empty.description`
- Shell 级不带模块前缀，直接 `shell.<area>.<name>`，如
  `shell.nav.settings`、`shell.common.cancel`、`shell.common.save`。
- 工作空间种子数据专用命名空间 `workspace.seed.<id>`（见 §5）。

**不允许**把整句话拆成多个 key 拼接（如 `common.hello` +
`common.world`）——多语言词序不同，拼接会在部分语言下产生语法错误的句子；需要插值就用
§3 的占位符。

## 3. 插值语法

```json
{ "notes.toast.deleted": "已删除「{title}」" }
```

```js
t("notes.toast.deleted", { title: note.title });
```

`t(key, params)` 只做简单的 `{name}`
字符串替换，不支持嵌套/条件语法（复杂度不值得为此引入模板引擎依赖）。数字/日期格式化一律用原生
`Intl.NumberFormat`/`Intl.DateTimeFormat`（零依赖，自动适配当前 locale），不在
i18n JSON 里存格式化后的字符串模板。

## 4. 回退链与缺失翻译提示

`t()`
查找顺序：`当前语言 → zh-CN → 原样返回 key`。开发模式（`DEPLOY_TARGET=local`）下命中"原样返回
key"分支时，通过 `shared/logger` 打一条 `warn`
级日志（`[i18n] missing key "notes.foo" for locale "en"`），生产环境静默降级，不打扰用户也不刷日志噪音。

## 5. 数据库存储的 i18n key（`i18n:` 前缀约定）

`core_workspaces.name`
列这种"系统种子数据需要多语言、用户自建数据不需要"的场景，用统一前缀区分：

```
name = "i18n:workspace.seed.default"   → 前端识别 "i18n:" 前缀，取后半段当 key 传给 t()
name = "我的旅行清单"                    → 没有前缀，直接展示字面量（用户自己输入的名字不需要翻译）
```

这是**唯一**允许数据库字段存 i18n key 的地方；其他模块新增类似需求前，先在
`docs/decisions/` 记一条 ADR 说明为什么现有模式不够用，避免这个例外被滥用扩散。

## 6. 语言切换 UI 与持久化

`<ds-lang-switch>`（Header 内，见 `Layout.md §3`）：下拉三选一。选择结果写入
`<html lang="...">` + `localStorage`（键 `pref:locale`）；如需跨设备同步，写入
`app_settings['settings:display']` 的 `locale`
字段（客户端本地值优先，`app_settings` 仅作新设备的初始默认值，语义与
`Workspace.md` 里 `pref:workspace` vs `settings:workspace` 的关系一致）。

## 7. 新增一种语言的步骤

1. 在所有 `i18n/*.json` 目录下新增对应 locale 文件（`shared/i18n/`
   与每个已存在模块的 `i18n/`）。
2. `shared/lib/locales.js` 的 `SUPPORTED_LOCALES` 常量数组追加该 locale。
3. `<ds-lang-switch>` 组件的选项列表自动读该常量，无需改组件代码。
4. `docs/i18n.md`（本文件）追加一行到 §0 支持语言列表（如未来需要）。

## 8. 复数规则

当前三种语言里中文没有复数变化，英文有简单的单复数区分。约定：涉及计数的文案统一用"
{count}
项"这类中性表达（中文天然不需要变位），英文文案人工维护单复数（`"{count} item" / "{count} items"`
各存一个 key，由调用方按 `count === 1` 选择 key），不引入 ICU MessageFormat
复数插件（复杂度/收益不成比例）。
