# Design.md — Nova 视觉设计原则

对应
[`ARCHITECTURE.md §6`](../ARCHITECTURE.md#6-设计系统nova--zinc)。这里是"怎么设计得像"，令牌的"是什么"在
`CSS.md`，组件的"API 是什么"在 `Components.md`。

## 1. 设计原则（按优先级）

1. **信息密度优先于装饰性留白**——用户打开一个页面应该在一屏内看到尽可能多有效信息，而不是被大块空白"呼吸感"稀释。这是对通用
   shadcn 模板常见问题（卡片上下左右留白过多）的刻意纠偏，具体收敛手段见
   `Layout.md §5`。
2. **克制的视觉层级**：颜色只用于语义（危险/警告/成功/主操作），不用于装饰；层级靠字号/字重/间距节奏区分，不靠加色块。
3. **边框优先于阴影**：默认状态的卡片/输入框用 1px
   `--color-border`，只有浮层（Dropdown/Dialog/Toast/Sheet）才用阴影令牌区分层级（见
   §3）。
4. **一致的圆角节奏**：圆角是「单一基准 + calc 档位 + 风格覆盖」三层
   （`docs/CSS.md §3`）：`--radius`（默认 0.625rem，主题设置可改）派生
   `--radius-sm`（×0.6，Badge/Checkbox）→ `--radius-md`（×0.8，常规控件）→
   `--radius-lg`（×1，容器级）→ `--radius-xl`（×1.4，Dialog/Sheet）→
   `--radius-full`（胶囊/圆形）；风格集（`style-*`）通过 `--ds-*-radius`
   再乘基准（如 luma 大圆角
   ×2.6）。禁止在组件间随意搭配不同圆角刻度制造"不统一感"，也禁止绕过档位直接写死数值。

## 2. 排版比例

| 令牌                      | 用途                                                  |
| ------------------------- | ----------------------------------------------------- |
| `--text-xs` (12px)        | 辅助说明、时间戳、Badge 文字                          |
| `--text-sm` (14px)        | 正文默认字号（信息密度优先，不用 16px 起步）          |
| `--text-base` (16px)      | 表单输入、按钮文字（与 Tailwind text-base=1rem 一致） |
| `--text-lg` (18px)        | 卡片标题、Section 标题                                |
| `--text-xl` (20px)        | 页面标题                                              |
| `--text-2xl`/`--text-3xl` | 极少使用，仅限首页级大数字展示                        |
| `--text-2xs` (10px)       | 色板示意标签等微字号                                  |

行高统一用 `--leading-tight`(1.25，标题) /
`--leading-normal`(1.5，正文)，避免每处单独定义。正文字体由主题设置写
`--font-sans-base`（默认 Inter Variable），**所有页面级标题（h1–h4）跟随
`--font-heading-base`**（全局规则在
`tokens/typography.css`，主题设置切标题字体时全站生效）；可变字体自托管于
`public/fonts/`。

## 3. 高度（Elevation）系统

| 场景             | 令牌                                                           | 说明                                                   |
| ---------------- | -------------------------------------------------------------- | ------------------------------------------------------ |
| 静态卡片         | 无阴影，仅 `--color-border`                                    | 密度优先，阴影会拉大视觉留白感                         |
| Dropdown/Popover | `--shadow-md`                                                  |                                                        |
| Dialog/Sheet     | `--shadow-lg`                                                  | 配合遮罩 `--color-overlay`（半透明黑，暗色模式下更淡） |
| Toast            | `--shadow-lg` + 1px 边框（两者叠加以在任意背景下都可辨识边界） |                                                        |

## 4. 动效

**全站无动效（与参考模板一致）**：`base/no-motion.css` 以
`* { animation: none !important; transition: none !important }` 无条件清零
一切动效——所有状态切换（悬停、展开/收起、弹层开合）均为瞬时完成。
约束与注入机制见 `CSS.md §9`（light DOM 规则穿不透 shadow，需经 `attachStyles()`
注入每个 shadow root；组件 JS 禁止依赖过渡事件）。

下列时长令牌**保留定义但当前不生效**（被 no-motion 压制），供未来整体
恢复动效时使用；恢复需整体重新评估，禁止逐组件解禁：

| 令牌              | 值                           | 预留用途（当前不生效）                          |
| ----------------- | ---------------------------- | ----------------------------------------------- |
| `--motion-fast`   | 120ms                        | 悬停态、图标旋转（Collapsible 箭头）            |
| `--motion-base`   | 180ms                        | Sidebar 展开/收起、Dropdown 展开                |
| `--motion-slow`   | 240ms                        | Sheet/Dialog 进出场                             |
| `--ease-standard` | `cubic-bezier(0.2, 0, 0, 1)` | 默认缓动，进出场一致，不用 `ease-in-out` 默认值 |

两层备份降级路径（在 no-motion 移除后才实际起作用）：
`prefers-reduced-motion: reduce` 命中时 `base/motion.css` 把上述时长令牌降为
`0.01ms`；`base/no-motion.css` 则无条件清零。运行时若确需等待过渡完成
（如弹层关闭后卸载），必须用 `waitForTransition()`（`shared/lib/dom.js`），
它在无动效下立即完成，禁止裸依赖 `transitionend` 或固定延时。

## 5. 图标使用规则

- 统一线性风格、`stroke-width: 1.75`，尺寸只用
  `--icon-sm`(16px)/`--icon-md`(20px)/`--icon-lg`(24px) 三档。
- 图标必须服务于信息（状态、类型、操作），不作纯装饰；空状态例外（一个大图标 +
  文案是被允许的克制装饰）。
- 图标与文字混排时，图标视觉重量与文字 `--text-sm` 对齐（用
  `--icon-sm`），基线用 `align-items: center` 而不是手动微调 `margin-top`。

## 6. 空状态 / 加载态 / 错误态

- **空状态**：`--icon-lg` 图标（灰度，`--color-fg-muted`）+ 一句话说明 +
  可选一个主操作按钮。不使用超过 2 行的说明文字。
- **加载态**：优先用 `<ds-skeleton>`
  骨架屏（还原真实内容的行数/宽度节奏），而不是居中大
  Spinner——骨架屏能让用户提前感知信息密度，符合 §1
  原则；仅在无法预知内容形状时（如提交表单后的等待）用小型内联 Spinner。
- **错误态**：内联展示在触发操作的位置附近（如表单字段下方），不用整页替换式错误页，除非是路由级
  404/500。

## 7. 信息密度指南（速查）

| 反例                               | 正做法                                                 |
| ---------------------------------- | ------------------------------------------------------ |
| 卡片内边距 `--space-8`（32px）起步 | `--space-3`/`--space-4`，用字号和图标补偿视觉重量      |
| 一个数字单独占一整个卡片           | 数字 + 同卡片内配 2-3 项相关次要信息（趋势/单位/时间） |
| 列表项之间用大间距分隔             | 用 1px 分隔线 + 紧凑内边距，`--space-2` 级别           |
| 侧栏收起态下留出大块空白按钮       | 收起态下用图标 + Tooltip，见 `Components.md#sidebar`   |

## 8. 无障碍基线

- 正文文字对比度 ≥ WCAG AA（4.5:1），令牌层的 `--color-fg` / `--color-bg`
  组合已在设计令牌阶段校验，组件禁止用 `--color-fg-muted` 承载正文级信息。
- 焦点态统一用 `--sidebar-ring`/`--ring` 令牌的 2px outline，禁止
  `outline: none` 而不提供替代焦点样式。
- 触控目标最小
  `2.5rem × 2.5rem`（40px），移动端断点下按钮/菜单项内边距按此校验。
