# docs/decisions/ — 架构决策记录（ADR）

每一次「存在多种合理选项、且影响后续开发」的架构取舍都应该在这里落一条记录，而不是只活在
PR 描述或聊天记录里。文件名 `000N-<slug>.md`，编号全局自增、不复用。

## 何时需要写 ADR

- 引入/替换任何工具链、依赖（含 vendoring，见 `../Vendoring.md §6` 的门槛）。
- 修改 `ARCHITECTURE.md` 里已经拍板的设计（尤其是 §20 开放决策的最终裁定）。
- 任何"性能 vs 一致性""安全 vs 便利性"之类的显式取舍。

## 模板

```markdown
# ADR 000N: <标题>

- 状态：提议 / 已采纳 / 已废弃（若废弃，指向替代它的 ADR）
- 日期：YYYY-MM-DD
- 相关模块/文档：<如 ARCHITECTURE.md §X, docs/Xxx.md>

## 背景

<为什么需要做这个决定，当时面临的约束是什么>

## 考虑过的选项

1. **选项 A**：<描述> — 优点 / 缺点
2. **选项 B**：<描述> — 优点 / 缺点

## 决定

<最终选择了哪个选项，一句话结论>

## 后果

<这个决定带来的取舍，尤其是"以后要为此付出什么代价">
```
